# Safari extension transport

## Goal

Match the Claude Code + Chrome experience in Safari: a browser extension gives the
mod page access, screenshots, console and network capture, file uploads and stable
tab ids, with setup limited to enabling the extension once. The AppleScript transport
from the first spec stays as the fallback.

## Architecture

```
mod (hooks/)  --unix socket HTTP-->  bridge daemon (bridge/bridge.mjs, node)
                                          ^
                                          | localhost HTTP long-poll
                                 Safari Web Extension (extension/)
                                   background.js  <-> content.js (page runtime)
```

Safari routes native messaging to the containing app, not to an outside program, so
the extension reaches Claude Code through a local daemon instead. The daemon is one
plain Node script with no dependencies. The mod starts it when it is not reachable
and talks to it with `$.http.fetch` over `~/.claude/safari-bridge.sock`. The daemon
is shared by every session on the machine; whichever session started it owns it.

## Components

- `extension/manifest.json`: Manifest v2 with a persistent background page (what
  Safari supports for a long-lived connection on macOS), `<all_urls>` content script,
  permissions `tabs`, `activeTab`, `webRequest`, `<all_urls>`, `http://127.0.0.1/*`.
- `extension/page-runtime.js`: the page runtime, now the single source. A script
  copies it into `hooks/page-script.ts` for the AppleScript transport.
- `extension/content.js`: loads the runtime, answers `{fn, args}` messages from the
  background page, installs the console hook in the page world, handles uploads.
- `extension/background.js`: long-polls the daemon for commands, runs them
  (tabs, navigate with load wait, page calls, captureVisibleTab scaled to CSS pixels,
  tab-scoped console and network buffers), posts results, reconnects forever.
- `bridge/bridge.mjs`: HTTP on the Unix socket for the mod (`POST /call`,
  `GET /status`, `GET /events`), HTTP on 127.0.0.1:47831 for the extension
  (`GET /ext/poll`, `POST /ext/result`, `POST /ext/events`). One command in flight
  per tab; 60 s default timeout.
- `hooks/io.ts`: the narrow capability surface (`run`, `spawn`, `fetch`, `home`, file
  reads and writes, `after`) that helper modules receive. The engine's validator refuses
  a module that passes `$` across an import, so `register.ts` alone touches `$` and
  builds this object from it per hook call.
- `hooks/transport.ts`: picks the extension when `GET /status` says it is connected
  (seen within 40 s), otherwise AppleScript. Exposes one `page(fn, args)` and
  `command(name, params)` surface to the tools.
- `hooks/register.ts`: the existing tools, now transport-neutral, plus
  `console_messages`, `network_requests`, `upload_file`, a `save_to_disk` option on
  screenshot, and the `/safari` command (status, start bridge, how to enable).
- `xcode/`: project generated by `safari-web-extension-converter`, built with
  `xcodebuild`; the built app registers the extension with Safari.

## Page-world JavaScript and console capture

Content scripts run in Safari's isolated world. The `console-hook.js` script is injected
into the page world at `document_start`; it wraps `console.*`, catches error events,
and relays entries to the content script with `postMessage`. The `javascript` tool
sends its expression the same way so it runs in the page world (page globals visible,
output captured); when a page's CSP refuses the hook, the expression runs in the
isolated world instead and the tool says so only through missing page globals.

## Tab ids

Extension transport uses Safari's numeric tab ids. AppleScript keeps `window:index`.
Tools accept either; `tabs_context` reports whichever transport is active.

## Error handling

Extension not connected: tools fall back to AppleScript silently and `tabs_context`
says which transport answered. Page not reachable (Safari internal pages, PDFs): one
sentence naming the tab. Content script missing (page loaded before the extension was
enabled): background injects it once with `tabs.executeScript`, then retries.

## Testing

Unit tests for the pure helpers. The daemon is exercised end to end with a fake
extension client in `bridge/bridge.test.ts`. The extension is verified live against
example.com and the httpbin form page.

## Setup on Safari 27

"Allow unsigned extensions", "Allow JavaScript from Apple Events" and "Add Temporary
Extension…" are in Safari > Settings > Developer, not the Develop menu. A rebuilt
extension is picked up only after Safari reloads it.

## Out of scope for this phase

GIF recording, trusted mouse and keyboard input (Safari has no debugger API).
